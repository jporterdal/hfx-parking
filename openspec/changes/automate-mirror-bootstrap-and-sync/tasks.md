Section 1 proves the one assumption everything else rests on: that `sync()` populates a truly empty database. Section 2 adds the lock, section 3 makes a layer failure local, and section 4 builds the worker on top of both. Section 5 is the readiness state and how the served application uses it. Section 6 reconciles the documentation and writes the Railway runbook. Section 7's Railway steps are retired: the repository owner deploys by hand, so they are not tasks in this change (see the note below); its last task, the full suite, was done.

Do section 1 first: if the empty-database run fails, the design's premise (D1, one worker over the existing sync) needs revisiting before anything is built on it.
